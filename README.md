Програмна система до кваліфікаційної (магістерської) роботи
«Адаптація методів розпізнавання образів для реалізації технології
«електронного носа»».

- Автор: Тарас Конопка, група ФеІм-24, спеціальність F3 – Комп'ютерні науки
- Науковий керівник: проф. Ігор Оленич

## Призначення

Система визначає речовину, що діяла на газовий сенсор, за знімком екрана
осцилографа (PNG) без числового експорту даних. Розрізняються чотири класи:

- `acetone` – пара ацетону;
- `ammonia` – пара аміаку;
- `ethanol` – пара етанолу;
- `RH` – фонова атмосфера з відносною вологістю (контрольний клас).

## Принцип роботи

1. Обрізання службового інтерфейсу осцилографа.
2. Виділення кривої сигналу HSV-маскою та перетворення маски на
   одновимірний сигнал.
3. Пошук фронтів методом гістерезису за рівнем і поділ сигналу на повні
   цикли (імпульси).
4. Контроль якості кожного імпульсу; непридатні фрагменти відкидаються.
5. Класифікація імпульсу однією з двох гілок:
   - гілка ознак – 35 числових ознак і сім моделей машинного навчання
     (LogReg, KNN, SVM, DecisionTree, RandomForest, GradientBoosting,
     XGBoost);
   - гілка зображень – вхід 192×96×2 (напівтоновий канал і маска кривої),
     HOG-дескриптори, заморожена MobileNetV2 або власна згорткова мережа
     2D-CNN.
6. Злиття прогнозів усіх імпульсів у рішення для знімка (зважене за якістю
   імпульсу) і видача класу з впевненістю.

Найкращий результат (групова крос-валідація GroupKFold(5), 445 знімків,
1253 імпульси) дає ансамбль HOG + XGBoost і 2D-CNN: F1-macro на рівні
знімка 0,980 ± 0,004. Окремо 2D-CNN досягає 0,977 ± 0,007, найкраща модель
на ознаках (SVM) – 0,930 ± 0,023.

## Системні вимоги

- ОС: Windows 10/11, Linux або macOS.
- Python 3.12 (перевірено на 3.12.10; TensorFlow 2.17 підтримує
  Python 3.9–3.12).
- Оперативна пам'ять: від 8 ГБ; вільне місце на диску: близько 3 ГБ
  (з урахуванням TensorFlow).
- Відеокарта не потрібна: усі моделі, зокрема 2D-CNN, навчаються на CPU.
- Git для клонування репозиторію.

## Встановлення

```bash
git clone https://github.com/We1zer/sensor_image_classification.git
cd sensor_image_classification

python -m venv venv
# Windows:
venv\Scripts\activate
# Linux / macOS:
source venv/bin/activate

pip install -r requirements.txt
```

Версії пакетів у `requirements.txt` зафіксовано навмисно: збережені моделі
навчено на scikit-learn 1.5.2, а `keras 3.6.0` сумісна з TensorFlow 2.17.
Оновлювати пакети не рекомендується.

Назва теки задає клас, номер у назві файлу – номер вимірювання. Щоб

синтетичні осцилограми (перед роботою з реальними даними їх слід

```bash
python generate_demo_data.py --n 30
```

## Порядок запуску

Навчені моделі в репозиторій не входять (теки `models/`, `features/`,
`processed/`, `results/` створюються під час роботи), тому перед першою
класифікацією систему потрібно навчити.

Крок 1. Побудова набору імпульсів і ознак та навчання базових моделей:

```bash
python app.py
# у меню обрати пункт 8 «Запустити повний pipeline»
```

Пункт 8 послідовно індексує набір даних, обробляє знімки, вирізає імпульси,
обчислює ознаки, навчає моделі гілки ознак і будує графіки в `results/`.

Крок 2. Навчання моделей для класифікації нових знімків на повному наборі:

```bash
python -m src.feature_model_store   # 7 моделей гілки ознак
python -m src.image_model_store     # HOG, MobileNetV2, 2D-CNN, ансамблі
```

Найдовший крок – навчання 2D-CNN на CPU (до кількох десятків хвилин
залежно від процесора), решта моделей навчаються за кілька хвилин.

Крок 3. Запуск веб-інтерфейсу:

```bash
python webapp.py
```

Після запуску відкрити в браузері адресу http://127.0.0.1:5000.

## Робота з веб-інтерфейсом

- `/` – стан проєкту та швидкі дії;
- `/dataset` – перегляд набору даних і переіндексація;
- `/pipeline` – побудова набору ознак (фонова задача з індикатором
  прогресу);
- `/training` – навчання та порівняння моделей гілки ознак;
- `/experiments` – запуск експериментів обох гілок і зведені таблиці;
- `/predict` – класифікація нового знімка;
- `/results` – графіки, матриці помилок і таблиці результатів.

Щоб класифікувати знімок, на сторінці `/predict` слід завантажити
PNG-файл осцилограми, обрати модель або ансамбль і натиснути кнопку
класифікації. Сторінка результату показує фінальний клас, впевненість,
імовірності за класами, прогноз для кожного імпульсу та покрокову обробку
знімка: рамку обрізання, маску, сигнал із порогами, межі імпульсів і
рішення контролю якості для кожного фрагмента. Якщо впевненість менша
за 0,55, система виводить попередження.

## Класифікація з командного рядка

```bash
# модель гілки ознак
python -m src.predict dataset/PNG-1ethanol/SDS00050.png

# модель або ансамбль гілки зображень
python -m src.predict_image dataset/PNG-1ethanol/SDS00050.png "2D-CNN"
```

## Відтворення експериментів

```bash
# обидві гілки паралельно (окремі процеси)
python run_experiments.py --branch both

# зведена таблиця всіх моделей за єдиним протоколом
python -m src.compare_all --with-cnn
```

Результати зберігаються в `results/` (таблиці CSV, матриці помилок),
журнали гілок – у `results/logs/`. Усі моделі оцінюються груповою
крос-валідацією GroupKFold(5) з групуванням за знімком і фіксованим
початковим значенням генератора випадкових чисел (42).

## Структура проєкту

```
sensor_image_classification/
├── dataset/              експериментальний набір знімків
├── src/                  модулі обробки, навчання та прогнозу
├── web/                  маршрути веб-інтерфейсу (Flask)
├── templates/, static/   HTML-шаблони, стилі, скрипти
├── app.py                консольне меню
├── webapp.py             запуск веб-інтерфейсу
├── run_experiments.py    запуск експериментів
├── generate_demo_data.py генерація синтетичних знімків
├── requirements.txt      залежності
└── docs/                 робочі нотатки розробки
```

Основні модулі `src/`:

- `image_preprocessing.py`, `signal_extraction.py` – обрізання
  інтерфейсу, HSV-маска, перетворення маски на сигнал;
- `pulse_segmentation.py`, `pulse_quality.py` – пошук фронтів, межі
  імпульсів, контроль якості;
- `feature_extraction.py`, `dataset_builder.py` – обчислення ознак,
  побудова набору імпульсів;
- `train_ml_models.py`, `evaluate.py`, `fusion.py` – навчання моделей на
  ознаках, крос-валідація, злиття рішень;
- `image_prep.py`, `image_methods.py` – вхід гілки зображень, HOG,
  MobileNetV2, 2D-CNN;
- `feature_model_store.py`, `image_model_store.py` – навчання на повному
  наборі, збереження моделей, ансамблі;
- `predict.py`, `predict_image.py`, `predict_trace.py` – класифікація
  нового знімка та покрокова візуалізація;
- `compare_all.py` – зведене порівняння всіх моделей.

## Можливі проблеми

- `DLL load failed ... An Application Control policy has blocked this
  file` (Windows) – Smart App Control блокує бінарні файли пакетів.
  Слід встановлювати саме версії з `requirements.txt`. Якщо блокування
  TensorFlow повторюється, Smart App Control потрібно вимкнути
  (Безпека Windows → Керування програмами й браузером) або запускати
  систему в Linux, WSL чи Google Colab. Гілка ознак працює і без
  TensorFlow.
- `No module named 'tensorflow.keras'` – встановлено несумісну версію
  keras; виконати `pip install keras==3.6.0`.
- Сторінка `/predict` не пропонує моделей – не виконано крок 2 розділу
  «Порядок запуску».
